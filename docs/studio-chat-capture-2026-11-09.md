# Busy-chat capture and profile-photo qualification

This follows [the image-message investigation](studio-chat-image-messages-2026-11-08.md). Evidence roots below are ignored directories: `M = native-qt/build-integration/memory-isolation-nov8/`, `I = native-qt/build-integration/capture-isolation-nov9/`, and `R = native-qt/build-integration/release-qualification-nov8/`. Public usernames, messages, screenshots, disposable profiles and recordings stay outside the commit. No public messages or purchases were made.

## Changes

- Kick profile lookups no longer run in the capture browser for every new author. A source-scoped fetch adapter returns a validated internal avatar reference; the native list resolves visible rows. Platform page fetches are unchanged. Public profile requests use no browser cookies or saved authentication, reject redirects, cap JSON at 16 KiB, and run at most twice per second. HTTP 429 pauses profile requests according to a bounded Retry-After value. The existing four-job limit, 4 MiB decoded-image cache and image validation remain in effect. Missing photos retain initials.
- Kick's hidden browser viewport is 8,192 pixels high. The platform batches busy chat roughly every 550 ms into a virtual list; a short viewport can skip rows in a large batch. Resizing the owning Qt window alone did not work: Windows reduced it to 1,061 pixels. Setting WebView2 bounds directly produced an actual 8,192-pixel viewport and approximately 258 rendered rows. The controller stays inside a hidden owner; no additional window appears on the desktop.
- Strictly validated Kick message UUIDs survive the bridge and native feed. `kick-compare-ids.py` compares those IDs, author and text with the independent public reference. It fails on missing/duplicate/unexpected IDs, altered content, incomplete reference coverage or arrivals outside five seconds. Gifts and reward notices without chat IDs have separate platform-event inputs and are not scored as ChatMessageEvent; they remain in the raw ledger.
- A companion Social Stream change skips Twitch clip-preview cards when extracting an ordinary message. The original link and viewer text remain; preview titles and curator attribution are excluded. The existing source is used directly, without a packaged-only patch. It is a separate repository change in `social_stream/sources/twitch.js`.
- Large rich messages are compacted to readable text before crossing the native message boundary. Inert template parsing retains image alternative text, line breaks and reply fields. The native 8,000-character text limit remains; input over the parsing budget remains subject to rejection. This fixes short emote-heavy messages whose generated image markup exceeded the limit.
- Twitch cheer images no longer repeat their amount in alternative text alongside the visible amount. The SSN source retains the image and visible label in HTML mode and emits the amount once in plain text.

Optional resource diagnostics also report numeric viewport height, chat-list height and rendered-row counts. They remain off by default, skip account windows, and do not inspect credentials, storage or response bodies. No browser debugging connection is used.

The companion Twitch formatting changes and extraction gates are committed locally as `a6fafde3` on Social Stream's `beta` branch. Nothing was pushed. Their packaged source hash is listed below; SSApp and extension runtimes were not exercised in this pass.
